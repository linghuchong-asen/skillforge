# 大纲模板（spec.md）

```
# Spec：<任务名称>

- 日期：yyyy-mm-dd
- 状态：待确认 / 已确认
- 作者：Codex（基于用户需求整理）

## 1. 背景与目标
<为什么要做，要达成什么>

## 2. 范围与功能要点
- FR-1：<可验证的功能要点>
- FR-2：...

## 3. 非目标（本期不做）
- <明确排除的范围>

## 4. 开放问题与假设
- Q1：<待用户决定的问题>
- 假设 A1：<合理假设，等待确认>
```

# 任务列表模板（tasks.md）

```
# Tasks：<任务名称>

- 日期：yyyy-mm-dd
- 状态：待确认 / 已确认
- 前置：spec.md 已确认后执行

## 任务清单

- [ ] T1（P0）：<任务描述> — 关联 FR-1，验收：<完成标准>，复杂度：<S/M/L>
- [ ] T2（P0）：<任务描述> — 关联 FR-1，验收：<完成标准>，复杂度：<S/M/L>
- [ ] T3（P1）：<任务描述> — 关联 FR-2，验收：<完成标准>，复杂度：<S/M/L>

## 依赖关系
<T1 → T2 → T3，或哪些可并行>

## 变更记录
<执行期间的结构变更（拆分/新增/移除）在此追加；格式：
- [日期] T3 拆分为 T3a/T3b — 原因：…，是否需用户确认：否/是>
```

# 验收清单模板（checklist.md）

```
# Checklist：<任务名称>

- 日期：yyyy-mm-dd
- 状态：执行中 / 全部通过 / 存在失败项

## 验收条目

- [ ] AC-1：<可操作、可验证的验收项> — 状态：未检 / 通过 / 失败 / 已移除（原因：…），备注：<说明>
- [ ] AC-2：<验收项> — 状态：未检
- [ ] AC-3：<验收项> — 状态：未检

## 变更记录
<与 tasks.md 的结构变更同步记录；格式：
- [日期] 新增 AC-3a（对应 T3a）— 原因：…>

## 说明
- 每条 AC 与 tasks.md 中的任务验收标准一一对应。
- 执行过程中实时更新状态；验证阶段逐项自检后回写最终结果。
- 结构变更后需重新核对 tasks.md ↔ checklist.md 对应关系。
```
